# Persistent Team

Persistent roles carry continuing responsibility. They are not personalities.
Invoke the smallest useful team and summarise findings before sharing them.

Use the knowledge curator when task results may create reusable knowledge,
new relationships, unresolved questions, stale entries or contradictions.

## Using a role as a review lens

These files are also the lenses to compose into a delegated review brief. Name
one or two, point the reviewer at the file, and say what that lens owns and what
belongs to another pass. A combination usually beats a single role — *architect +
tech-lead* covers boundaries and implementation coherence together. See
`dispatching-review-passes`.
